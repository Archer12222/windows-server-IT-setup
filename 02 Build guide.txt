02 - BUILD GUIDE
================

The order and commands used to build the lab. Passwords are never stored in
this repository; choose your own when you see a prompt.

Conventions: PowerShell commands are shown as-is. The domain is corp.lab, the
server is WindowsServer, and the lab network is 192.168.56.0/24.


PHASE 0 - PREPARATION (VirtualBox)
----------------------------------
1. Download the Windows Server evaluation ISO and a Windows 11 ISO from
   Microsoft.
2. In VirtualBox, open the Network Manager and DISABLE the DHCP server on the
   host-only network (the Windows Server DHCP role will serve addresses).
3. Create each VM with two adapters: Adapter 1 = NAT, Adapter 2 = Host-Only.
4. When creating a VM, check "Skip Unattended Installation". The automatic
   install can pick the wrong edition (Windows 11 Home, or Server Core).


PHASE 1 - SERVER BASE
---------------------
1. Install Windows Server 2025 Standard Evaluation. (This build used the
   Server Core edition; pick the "Desktop Experience" edition instead if you
   want a GUI.)
2. Sign in and use SConfig (menu option 15 exits to PowerShell).
3. Rename the server and restart:

     Rename-Computer -NewName WindowsServer -Restart

4. Identify the Host-Only adapter (the one without a 10.0.2.x address):

     Get-NetAdapter
     Get-NetIPAddress

5. Set a static IP and DNS on the Host-Only adapter (adjust the adapter name):

     Set-NetIPInterface -InterfaceAlias "Ethernet 2" -Dhcp Disabled
     New-NetIPAddress -InterfaceAlias "Ethernet 2" -IPAddress 192.168.56.10 -PrefixLength 24
     Set-DnsClientServerAddress -InterfaceAlias "Ethernet 2" -ServerAddresses 127.0.0.1

6. Verify:

     hostname
     Get-NetIPAddress -AddressFamily IPv4 | Format-Table InterfaceAlias, IPAddress, PrefixLength
     Get-DnsClientServerAddress -AddressFamily IPv4
     ping 8.8.8.8

7. Take a VM snapshot.


PHASE 2 - DOMAIN, DNS, DHCP
---------------------------
1. Install the roles:

     Install-WindowsFeature AD-Domain-Services, DNS, DHCP -IncludeManagementTools

2. Create the forest (prompts for a recovery/DSRM password; the server
   restarts):

     Install-ADDSForest -DomainName "corp.lab" -DomainNetbiosName "CORP" -InstallDns

   Notes: avoid ".local" as a domain suffix (it can conflict with mDNS). The
   DNS delegation warning is normal in a lab.
3. After the restart, sign in as CORP\Administrator and verify:

     Get-ADDomain
     Get-Service NTDS, DNS, Netlogon
     nslookup corp.lab

4. Add a DNS forwarder so the lab can resolve internet names:

     Add-DnsServerForwarder -IPAddress 8.8.8.8

5. Configure and authorize DHCP:

     Add-DhcpServerInDC -DnsName WindowsServer.corp.lab -IPAddress 192.168.56.10
     Add-DhcpServerv4Scope -Name "LabScope" -StartRange 192.168.56.100 -EndRange 192.168.56.200 -SubnetMask 255.255.255.0 -State Active
     Set-DhcpServerv4OptionValue -DnsServer 192.168.56.10 -DnsDomain corp.lab

6. Verify:

     Get-DhcpServerInDC
     Get-DhcpServerv4Scope

7. Take a VM snapshot.


PHASE 3 - ACTIVE DIRECTORY STRUCTURE
------------------------------------
Note: you cannot create top-level OUs named "Users" or "Computers" because
built-in containers with those names already exist (see the troubleshooting
log). Create a parent OU first.

     New-ADOrganizationalUnit -Name "Company" -Path "DC=corp,DC=lab"
     New-ADOrganizationalUnit -Name "Users" -Path "OU=Company,DC=corp,DC=lab"
     New-ADOrganizationalUnit -Name "Computers" -Path "OU=Company,DC=corp,DC=lab"
     New-ADOrganizationalUnit -Name "Groups" -Path "OU=Company,DC=corp,DC=lab"

     New-ADGroup -Name "Staff" -GroupScope Global -Path "OU=Groups,OU=Company,DC=corp,DC=lab"
     New-ADGroup -Name "IT-Helpdesk" -GroupScope Global -Path "OU=Groups,OU=Company,DC=corp,DC=lab"

     New-ADUser -Name "Staff User" -SamAccountName sstaff -UserPrincipalName sstaff@corp.lab -Path "OU=Users,OU=Company,DC=corp,DC=lab" -AccountPassword (Read-Host -AsSecureString "Password") -Enabled $true
     New-ADUser -Name "IT Tech" -SamAccountName ittech -UserPrincipalName ittech@corp.lab -Path "OU=Users,OU=Company,DC=corp,DC=lab" -AccountPassword (Read-Host -AsSecureString "Password") -Enabled $true

     Add-ADGroupMember -Identity Staff -Members sstaff
     Add-ADGroupMember -Identity IT-Helpdesk -Members ittech

     redircmp "OU=Computers,OU=Company,DC=corp,DC=lab"

Passwords must meet the domain complexity rules.

Verify:

     Get-ADOrganizationalUnit -Filter * | Select-Object Name, DistinguishedName
     Get-ADUser -Filter * | Select-Object Name, SamAccountName


PHASE 4 - JOINING WORKSTATIONS
------------------------------
Use Windows 11 PRO (Home cannot join a domain). During setup choose "I don't
have a product key" and select Pro, or pick the Pro edition in VirtualBox.

On each workstation (PowerShell as administrator):

1. Point DNS at the domain controller on BOTH adapters, so the client never
   asks another DNS server for corp.lab:

     Get-NetAdapter
     Set-DnsClientServerAddress -InterfaceAlias "Ethernet 2" -ServerAddresses 192.168.56.10
     Set-DnsClientServerAddress -InterfaceAlias "Ethernet" -ServerAddresses 192.168.56.10
     ipconfig /flushdns
     Resolve-DnsName corp.lab

   Resolve-DnsName must return 192.168.56.10 before you try to join.
   (Optional: lower the host-only adapter metric so it is preferred:
    Set-NetIPInterface -InterfaceAlias "Ethernet 2" -InterfaceMetric 10)

2. Rename the computer, then join the domain:

     Rename-Computer -NewName <name> -Restart
     Add-Computer -DomainName corp.lab -Credential CORP\Administrator -Restart

3. Sign in with a domain account (CORP\sstaff or CORP\ittech) and verify:

     whoami
     gpresult /r

   On the server, Get-ADComputer -Filter * should list the workstation in the
   Computers OU.

4. Do not clone a workstation after it has joined the domain. Clone from a
   clean snapshot taken BEFORE the join, change the computer name, and
   reinitialize the VM's MAC addresses.


PHASE 5 - IT WORKSTATION TOOLS AND DELEGATION
---------------------------------------------
1. Install RSAT on the IT workstation (elevated PowerShell, local admin):

     Add-WindowsCapability -Online -Name Rsat.ActiveDirectory.DS-LDS.Tools~~~~0.0.1.0
     Add-WindowsCapability -Online -Name Rsat.GroupPolicy.Management.Tools~~~~0.0.1.0
     Add-WindowsCapability -Online -Name Rsat.Dns.Tools~~~~0.0.1.0
     Add-WindowsCapability -Online -Name Rsat.DHCP.Tools~~~~0.0.1.0

2. Delegate password resets. Open AD Users and Computers with domain admin
   credentials (the IT account itself has no rights to delegate):

     runas /netonly /user:CORP\Administrator "mmc.exe %SystemRoot%\system32\dsa.msc"

   Then: right-click the Users OU > Delegate Control > add IT-Helpdesk >
   "Reset user passwords and force password change at next logon" > Finish.
   (To allow unlocking accounts, run the wizard again with a custom task for
   user objects and grant Read/Write on the lockoutTime property.)

3. Test as the tech: sign in as CORP\ittech, open dsa.msc normally, and reset
   the staff user's password. Resetting an account outside the delegated OU
   (for example the built-in Administrator) should be denied.


PHASE 6 - OSTICKET ACCESS BY NAME
---------------------------------
Pre-existing: an Ubuntu Server VM running osTicket 1.18.1 on Apache and
MariaDB. [Add your osTicket installation steps here.]

1. Give the osTicket server a Host-Only adapter on the lab network (it
   received 192.168.56.101 from the DC's DHCP). Consider a DHCP reservation
   so the address stays fixed:

     Add-DhcpServerv4Reservation -ScopeId 192.168.56.0 -IPAddress 192.168.56.101 -ClientId "<MAC-address>" -Name "osticket"

2. Add a DNS record on WindowsServer:

     Add-DnsServerResourceRecordA -Name osticket -ZoneName corp.lab -IPv4Address 192.168.56.101

3. Check the web server is listening and not firewalled (on the Ubuntu VM):

     sudo ss -tlnp
     sudo ufw status

4. Make the site root open osTicket directly: set DocumentRoot in the Apache
   site file to the osTicket folder, then:

     sudo apache2ctl configtest
     sudo systemctl reload apache2

5. In the osTicket admin panel, Settings > System, set the Helpdesk URL to
   http://osticket.corp.lab/ and save.

6. From a workstation, test:

     Resolve-DnsName osticket.corp.lab
     Test-NetConnection osticket.corp.lab -Port 80

   Browse to http://osticket.corp.lab/ (include "http://" so the browser does
   not treat the name as a search).
